Now we have blocked the download of files when slack is being used.
But what if they send a link using wetransfer, dropbox, teams?

One thing you can see if encrypted zip-files is even used within the company. If this is not being used, you can also decide to block encrypted zip files in general.

For this we will look at the profile again. However now we will look at the File Filter. This will now count for all the files, doesn't matter which app is being used.

![Highlight file filter](/images/Inside_Profile_Highlight_FileFilter.jpg)

Now there is an option to block password-protected files. But keep in mind that it also counts for other file types than zip files. No password protected file will be allowed in the traffic where this profile is being used.

![Block password protected](/images/Inside_Profile_Inside_FileFilter_BlockPassword.jpg)

Since the profile is the same, you don't need to create any other policy. If you would have deleted the policy already, you can make a similar policy like below.

![Policy encrypted file](/images/Policy_encrypted_file.jpg)

If you head back to the Windows client and you try to download the file again.

![alt text](</images/image (9).jpeg>)

You will see that the download keeps loading and nothing is happening. Again there won't be any replacement message. FortiSASE will just block the download.

![alt text](</images/image (8).jpeg>)

This can also be verified with FortiSASE. If you would go to the policies, right-click on a policy and click "show mathing logs", you will be transferred to the traffic logs with a filter already enabled. This filter is based on the policy UUID.

![alt text](/images/Logs_Blocked_Enctyped_File.jpg)

However in the traffic logs above, you will still see that Slack is being mentioned. The actual blocking of the file is being done by the file filter. You can head over to the security events and there you will see that there is a log message within file filter where it's mentioned that there was a file blocked by the file filter.

![alt text](/images/File_Filer_Blocked_Log.jpg)

If you open the log message, you can again look at it into details.

![alt text](/images/File_Filer_Blocked_Log_Detailed.jpg)
